# PRD: 개인용 할 일 관리 앱

- 작성일: 2026-11-04
- 상태: 초안

## 1. 개요

하루 10~20개 정도의 할 일을 빠르게 적고, 끝낸 일을 체크하고, 오늘 얼마나 진행했는지 한눈에 보는 개인용 웹 앱.
서버·계정·빌드 도구 없이 브라우저만으로 동작하고, 새로고침이나 브라우저 재시작 후에도 데이터가 유지된다.

## 2. 목표와 비목표

### 목표
- 할 일 하나를 추가하는 데 5초 안에 끝난다(입력 후 Enter).
- 새로고침·탭 닫기 후에도 데이터가 사라지지 않는다.
- 업무/개인/공부 카테고리로 나눠 보고, 전체 진행률을 즉시 확인한다.
- 순수 JavaScript(ES6+), HTML, CSS만 사용한다. 외부 라이브러리·프레임워크·빌드 과정 없음.

### 비목표 (이번 범위에서 제외)
- 로그인, 다중 사용자, 서버 동기화, 기기 간 공유
- 마감일 알림, 반복 일정, 하위 작업, 우선순위, 태그
- 카테고리 추가/삭제(3개 고정)
- 모바일 앱 포장(PWA 포함). 단, 모바일 브라우저에서 깨지지 않게 반응형은 지원한다.

## 3. 사용자와 사용 시나리오

- 사용자: 본인 1명. 하루 10~20개의 할 일을 다룬다.
- 시나리오 1: 아침에 할 일 10여 개를 카테고리별로 빠르게 입력한다.
- 시나리오 2: 하루 동안 완료한 일을 체크하고, 상단 진행률로 달성도를 확인한다.
- 시나리오 3: 업무 항목만 모아 보며 집중한다.
- 시나리오 4: 오타를 수정하거나 필요 없어진 항목을 삭제한다.

## 4. 기능 요구사항

우선순위: P0 = 필수, P1 = 있으면 좋음.

### 4.1 할 일 추가 (P0)
- 텍스트 입력창과 카테고리 선택(기본값: 직전에 선택한 카테고리)을 두고, Enter 또는 [추가] 버튼으로 등록한다.
- 공백만 입력하면 등록하지 않는다. 앞뒤 공백은 제거한다.
- 최대 길이 100자. 초과 입력은 막는다.
- 등록 후 입력창을 비우고 포커스를 유지한다(연속 입력).
- 새 항목은 목록 맨 아래에 추가한다.

### 4.2 할 일 수정 (P0)
- 항목 텍스트를 더블클릭하거나 [수정] 버튼을 누르면 인라인 편집 상태가 된다.
- Enter로 저장, Esc로 취소한다. 포커스가 벗어나면 저장한다.
- 빈 문자열로 저장하면 수정이 취소되고 기존 값을 유지한다.
- 카테고리도 수정할 수 있다(편집 중 선택 또는 항목의 카테고리 뱃지 클릭).

### 4.3 할 일 삭제 (P0)
- 항목마다 [삭제] 버튼을 둔다.
- 실수 방지를 위해 삭제 직후 "실행 취소" 토스트를 5초간 보여준다(확인 팝업은 쓰지 않는다).
- "완료된 항목 모두 삭제" 버튼을 둔다(P1).

### 4.4 완료 체크 (P0)
- 체크박스로 완료/미완료를 전환한다.
- 완료 항목은 취소선과 흐린 색으로 표시한다.
- 체크 시 진행률이 즉시 갱신된다.
- 완료한 시각은 기록만 한다(화면 표시는 하지 않음).

### 4.5 카테고리 분류 (P0)
- 카테고리는 **업무 / 개인 / 공부** 3개로 고정한다.
- 각 항목은 카테고리 뱃지(색상 + 텍스트)를 가진다. 색에만 의존하지 않고 글자도 함께 표시한다.
- 상단 필터 탭: **전체 / 업무 / 개인 / 공부**. 선택한 탭만 목록에 보인다. 선택 상태도 저장한다.

### 4.6 진행률 보기 (P0)
- 상단에 "완료 N / 전체 M (P%)"와 진행 바를 표시한다.
- 전체 기준 진행률과, 카테고리별 진행률(예: 업무 3/5)을 함께 보여준다.
- 항목이 0개면 "할 일을 추가해 보세요"를 표시하고 진행률은 0%로 처리한다(0으로 나누기 방지).
- 진행률은 현재 필터와 무관하게 전체 항목 기준으로 계산하고, 카테고리별 수치는 항상 보인다.

### 4.7 데이터 유지 (P0)
- 모든 변경(추가/수정/삭제/체크/필터 선택)은 즉시 `localStorage`에 저장한다.
- 앱을 열 때 저장된 데이터를 불러와 렌더링한다.
- 저장 데이터가 없거나 JSON이 손상되었을 때는 빈 목록으로 시작하고, 앱이 멈추지 않아야 한다. 손상 데이터는 덮어쓰기 전에 별도 키(`todo-app:backup`)에 보관한다.
- `localStorage` 접근이 막힌 경우(시크릿 모드 등) 화면 상단에 "저장이 되지 않습니다" 경고를 표시하고 메모리에서만 동작한다.

### 4.8 선택 기능 (P1)
- JSON 내보내기/가져오기(백업).
- 항목 드래그로 순서 변경.
- 다크 모드(시스템 설정 따라가기).

## 5. 데이터 모델

`localStorage` 키: `todo-app:v1`

```json
{
  "version": 1,
  "filter": "all",
  "todos": [
    {
      "id": "k3x9a1f2",
      "text": "주간 보고서 작성",
      "category": "work",
      "done": false,
      "createdAt": 1762230000000,
      "completedAt": null
    }
  ]
}
```

| 필드 | 타입 | 설명 |
|---|---|---|
| id | string | 고유값. `crypto.randomUUID()` 사용, 미지원 시 시간+난수 |
| text | string | 1~100자 |
| category | `"work"` \| `"personal"` \| `"study"` | 화면 표시는 업무/개인/공부 |
| done | boolean | 완료 여부 |
| createdAt | number | 생성 시각(ms) |
| completedAt | number \| null | 완료 시각, 미완료면 null |
| filter | `"all"` \| 카테고리 | 마지막 선택한 필터 |

`version` 필드는 이후 스키마 변경 시 마이그레이션에 사용한다.

## 6. 화면 구성

단일 페이지, 위에서 아래로 다음 순서:

1. **헤더**: 앱 이름, 오늘 날짜
2. **진행률 영역**: 전체 진행 바 + "완료 N / 전체 M (P%)" + 카테고리별 수치
3. **입력 영역**: 텍스트 입력, 카테고리 선택, [추가]
4. **필터 탭**: 전체 / 업무 / 개인 / 공부
5. **목록**: 체크박스 · 텍스트 · 카테고리 뱃지 · [수정] [삭제]
6. **푸터**: "완료된 항목 삭제" (P1)

빈 상태, 저장 불가 경고, 실행 취소 토스트 UI를 포함한다.

## 7. 비기능 요구사항

- **기술**: HTML + CSS + 순수 JavaScript(ES Modules 없이 단일 `script.js` 또는 `type="module"`). 외부 의존성 0.
- **파일 구성(안)**: `index.html`, `style.css`, `app.js`. 더블클릭으로 `index.html`을 열어도 동작해야 한다.
- **성능**: 항목 20개 기준 모든 동작이 체감 지연 없이 반영된다. 항목 수백 개까지도 문제없어야 한다.
- **보안**: 사용자 입력은 `innerHTML`로 넣지 않고 `textContent`로 렌더링해 XSS를 막는다.
- **접근성**: 키보드만으로 모든 기능을 쓸 수 있고(Tab, Enter, Esc), 체크박스에 레이블을 연결하며, 텍스트 대비를 충분히 확보한다.
- **호환성**: 최신 Chrome, Edge, Firefox, Safari. 화면 폭 360px 이상에서 가로 스크롤이 생기지 않는다.
- **코드 품질**: 상태(state) 한 곳에서 관리하고, 상태 변경 → 저장 → 렌더링 흐름을 하나로 통일한다.

## 8. 수용 기준 (완료 정의)

- [ ] 할 일을 추가하면 목록에 나타나고, 새로고침 후에도 그대로 남아 있다.
- [ ] 공백만 입력하면 추가되지 않는다.
- [ ] 항목을 수정·저장하면 반영되고, Esc로 취소하면 원래 값으로 돌아간다.
- [ ] 항목을 삭제하면 사라지고, 5초 안에 "실행 취소"로 복구할 수 있다.
- [ ] 체크하면 취소선이 생기고 진행률이 즉시 바뀐다. 체크 해제도 된다.
- [ ] 필터 탭을 바꾸면 해당 카테고리만 보이고, 새로고침 후에도 선택이 유지된다.
- [ ] 진행률은 필터와 무관하게 전체 기준이며, 항목이 0개여도 오류가 없다.
- [ ] 20개 항목에서도 모든 동작이 즉각적이다.
- [ ] `localStorage` 값을 일부러 망가뜨려도 앱이 열리고 빈 목록으로 시작한다.
- [ ] `<script>` 같은 문자열을 입력해도 실행되지 않고 글자 그대로 보인다.
- [ ] 키보드만으로 추가·수정·삭제·체크가 가능하다.

## 9. 구현 단계(제안)

1. **뼈대**: HTML 구조, 기본 스타일, 상태 객체와 `render()` 함수.
2. **핵심 CRUD + 저장**: 추가/체크/삭제 + `localStorage` 저장·복원.
3. **수정·카테고리·필터**: 인라인 편집, 뱃지, 필터 탭.
4. **진행률**: 전체·카테고리별 진행률, 빈 상태 처리.
5. **마감 작업**: 실행 취소 토스트, 에러 처리(손상 데이터, 저장 불가), 접근성·반응형 점검.
6. **P1 항목**: 백업(내보내기/가져오기), 순서 변경, 다크 모드 중 선택.

## 10. 미해결 질문

- 완료 항목을 목록 하단으로 자동 이동할까, 제자리에 둘까? (기본안: 제자리)
- 날짜가 바뀌면 완료 항목을 자동으로 비울까, 계속 쌓아 둘까? (기본안: 자동 삭제하지 않음. 필요하면 "완료 항목 삭제"로 정리)
- 화면 언어는 한국어로 고정해도 되는가? (기본안: 한국어 고정)
